# FastaGuard v0.7.0 — Operational Trust

FastaGuard v0.7.0 hardens the existing assembly preflight contract for routine
workflow use. This release focuses on deterministic outputs, explicit policy
scope, and machine-readable downstream decisions; it does not add a new
biological profile.

## Output Bundles And Safe Publication

Write all four single-file reports with one command:

```bash
fastaguard sample.fa --outdir reports --prefix sample-01
```

The final bundle names are:

```text
reports/sample-01.fastaguard.html
reports/sample-01.fastaguard.json
reports/sample-01.fastaguard.tsv
reports/sample-01.fastaguard_mqc.json
```

Output paths use no-clobber validation. If any requested final path exists, the
command exits `3` without publishing reports; use `--force` to replace the exact
requested final paths. Without `--force`, final publication also refuses to
replace entries created after preflight. Exact four-name guarantees apply to
`--outdir` bundles. For explicit output paths, each requested report is staged
to a temporary file before any final name is published. After all requested
reports serialize successfully, publication is not atomic as a set: final
renames are sequential.

## NCBI Genome Policy Scope

`--gate submission --submission-target ncbi` records the policy ID
`ncbi_genome`. The policy is FASTA preflight only and cites the
[NCBI Genome Submission Guide](https://www.ncbi.nlm.nih.gov/genbank/genomesubmit/).
The policy snapshot is dated `2026-08-21`. It checks first-token SeqIDs against
the 1–49 ASCII-byte `[A-Za-z0-9_.:*#-]` rule, the fixed 200-base minimum record
length, and terminal Ns.

The policy does not validate annotation, taxonomy, contamination, metadata, or
repository acceptance. It does not replace official NCBI validation, NCBI FCS,
or downstream biological QC.

The v0.7 report schema and finding catalog are versioned `0.7.0` for the new
required gate fields, policy provenance, expected-size evidence, and NCBI
finding IDs. Historical v0.6 evidence remains on its authentic `0.5.0`
contract.

## Exit And Downstream Gate Contract

```text
0 = completed report generation for PASS, WARN, and FAIL results
2 = argument parsing error
3 = configuration, input-access/I/O, runtime, or output-write error
```

Exit `0` means the requested report set completed, not that the FASTA passed a
QC policy. Read JSON for downstream decisions.

`machine_summary.safe_for_downstream` is conservative and true only for PASS.
`gate.can_continue` answers whether the selected gate has blocking findings. A
WARN report can have `gate.can_continue = true`; use `gate.status`,
`gate.can_continue`, and `gate.blocking_findings` together for routing.

## Release Archive

Release archives contain one top-level directory with the executable,
`README.md`, `LICENSE`, and the versioned `schema/` contract assets.

## Scope

FastaGuard remains assembly-first, database-free FASTA preflight. Transcriptome,
protein, and reference-panel profiles remain separately scoped future work.
